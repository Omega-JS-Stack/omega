### Fixed
- Devkit vendor tool died with `ENAMETOOLONG` on backend-manager's dist: `jetpack.find` follows symlinks during traversal (matching exclusions don't prune the walk), so the host-dist scan recursed forever through the self-test fixture's circular `backend-manager → package root` symlink. The scan now uses a symlink-safe walker that also skips `node_modules` and the vendor output — fixture/dependency code inside dist is not host code and is neither scanned nor rewritten. Regression-tested with a circular-symlink + node_modules fixture (devkit suite 32 passing).
- Sandbox `test:backend` never actually worked from the brand root: `npm run test:offline --workspace=apps/backend` resolved workspaces against the MONOREPO root (sandbox-brand is itself a root workspace and workspace globs don't recurse), so the flag found nothing — the corpus had only ever been run from inside `apps/backend`. Now `cd apps/backend && npm run test:offline`; CI's sandbox job would have failed on first push.
- `packages/client` (web-manager) had **no auth-emulator support** — Firestore had a `FIREBASE_EMULATOR_CONNECT` path but auth never called `connectAuthEmulator`, so signin/signup against an emulated backend silently hit LIVE Firebase Auth. Found by the cross-stack e2e (dogfood catch).
- `packages/client` emulator-mode **account reads hit LIVE Firestore**: the emulator connect lived only in the lazy firestore module, but the auth module reads accounts via `manager.firebaseFirestore` directly — unless page code happened to touch `manager.firestore()` first, account fetches went to production. Suite unchanged at 73 passing.

The runner now passes `emulatorPorts.firestore` through.
