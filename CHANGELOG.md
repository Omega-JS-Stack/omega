- **@omegajs/manager: the migrations service — flag-gated Firestore data migrations with the two canonical BEM-schema migrations (checkpoint 53).** The service runs **only with `--migration`** (bare = all, `--migration=<name>` = one; unknown names skip with the available list), so a normal manage run never touches collection data; it sits between account and testing (23 services), after the deployed backend is current. The ported **framework** is omega-manager's migration runner rebuilt on REST: per-collection fix pipelines with batched iteration, all of a doc's fixes merged into **one leaf-masked REST patch** (overlapping ancestor/descendant paths conflict-resolved first; deletes are masked paths absent from the body — `FieldValue.delete()` became a local identity sentinel, no firebase-admin), `__delete__`/`__logs__` fix sentinels, before/after snapshots + `_summary.json` under `.omega/migrations/{collection}/{ts}/`, `--limit` / `--ids` / `--verbose` (new CLI pass-throughs), and schema validation via the ported validator — with fix/write failures and schema-invalid docs downgrading the service to **warned** (omega-manager printed the ⚠ but reported success).
