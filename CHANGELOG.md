## [Unreleased]

### Changed
- **`packages/desktop` (electron-manager) reads `config/omega.json5` — the legacy `config/electron-manager.json` is no longer read anywhere** (dual-read cancelled by design: implement the new way, document the migration). `Manager.getConfig()` and the dev-mode boot fallback resolve through the vendored `@omegajs/config` (shared sections top-level, `targets.desktop` overlaid, brand-monorepo walk-up); packaged apps carry the RESOLVED config in `EM_BUILD_JSON`; boot + `gulp audit` validate against the shared schema (EM's own `src/config/schema.js` + `src/utils/validate-config.js` are deleted — they were the seed). Per-OS config moved `targets.{mac,win,linux}` → `platforms.{mac,win,linux}`. Consumers get a `require('electron-manager/config')` export (the vendored loader) — the scaffolded workflow's snap/signing gates use it instead of raw JSON5 reads. Migration is a one-time file conversion (mapping table in the monorepo's `docs/config.md`); existing consumers must convert when they take this release. Gates: EM suite 751 passing / 5 designed skips (pre-flip baseline), pack-smoke 9/9 (vendored loader + export + secret hard-fail from a scratch install, no legacy file in the tarball), 17 EM docs swept.

### Added
- `docs/config.md` — the omega.json5 format spec (locations, shape, resolution chain, hard rules, validation) + per-framework migration mapping tables (EM's is live; BEM/UJM/omega-manager rows staged for their flips).
- `@omegajs/config` (private workspace package) — the single `omega.json5` format for every OMEGA project type: `loadConfig(projectDir, target, { defaults })` discovers `config/omega.json5` (or `functions/config/omega.json5` for standalone backends), walks up to the brand root in a brand monorepo, and resolves one agnostic deep-merge chain (`defaults ← brand shared ← brand targets[t] ← app shared ← app targets[t]` — target sections overlay the top level, so any shared key inside a target entry overrides per-surface). Key presence under `targets` = target enabled (`enabled` flag + `getEnabledTargets()`); `hasOmegaConfig()` is the frameworks' dual-read probe; `SHARED_SECTIONS` is the enumeration omega-manager's disperse will use instead of hardcoding. The validator is EM's proven schema engine ported verbatim (required/type/match/enum; findings return as errors so audit can throw while boot warns), with the shared schema seeded from EM's entries, desktop refinements from EM's real schema (per-OS `targets` renamed `platforms`), and backend refinements from the sandbox's real BEM config. Hard fails: secret-shaped keys (`/(secret|privateKey|apiSecret)$/i`) anywhere in a raw file throw before any merge, and the legacy `targets` ARRAY form throws loudly instead of mangling. 34 tests green; CI test job gained the config suite. `toSiteGlobal()` deferred to the Phase-2 A0 slice (needs the real Jekyll `site.*` usage audit); framework dual-read adoption comes next as old-name minors (EM canary is the gate).
- `packages/backend` (backend-manager): consumer `public/*` is now **generated, never tracked** — `templates/_.gitignore` ignores `/public/`, and the boilerplate (index.html + 404.html, templated with the brand URL from the consumer's JSON5 config) is written by one shared generator (`src/cli/utils/public-files.js`): setup overwrites authoritatively, while `mgr emulator`/`mgr test`/`mgr deploy` fill it in when missing — a fresh clone has no `public/` at all and firebase-tools won't boot or deploy hosting without it. The sandbox consumer dogfooded the real `mgr setup` gitignore merge and untracked its copies. Gates: fresh-clone corpus (1203 passing after deleting `public/`), fresh-clone e2e 11/11 (regenerated with the real brand URL), standalone suite, pack-smoke incl. JSON5-config + fill-if-missing checks.
- `packages/backend` (backend-manager) adopted the devkit shims: `src/cli/utils/safe-install.js` and `src/cli/utils/attach-log-file.js` are now one-line shims over `@omegajs/devkit` (same pattern as extension/desktop — both BEM copies were functionally identical to the canonical versions; only behavior delta is the already-standard `# omega log` file header). BEM keeps its own route/console logging (wonderful-log) — there is no framework logger to shim. All four frameworks now vendor devkit. Gates: standalone suite, sandbox corpus 1203 passing, cross-stack e2e 11/11, pack-smoke incl. shim-load-from-consumer checks.
- `packages/backend` (backend-manager) adopted `@omegajs/account`: `src/manager/helpers/user.js` (schema + engine + constructor, 408 lines) became a ~50-line thin wrapper over the shared engine — zero call-site changes (`new User(Manager, settings).properties` and `User.resolveSubscription` unchanged), with BEM injecting the real `$uuid`/`$randomId`/`$apiKey` generators (uuid v4, `Manager.Utilities().randomId({ size: 8 })`, uid-generator). Both drifted copies of the account schema are now gone — BEM and web-manager resolve user docs through the same engine. Because the shipped test corpus deep-requires `src/` in consumers (where the private package can't resolve), the wrapper falls back from the bare specifier to the copy vendored into `dist/vendor/account/` — the path resolves at the same depth from both `src/` and `dist/`. Gates: account golden master 31/31 against the wrapped user.js, BEM standalone suite, sandbox corpus 1203 passing, cross-stack e2e 11/11 (the doc's `api.clientId` generated by the wrapped user.js in the emulator runtime), pack-smoke incl. a new consumer-style src deep-require check.
- `packages/backend` (backend-manager) gained its **dist layer** — the structural outlier is harmonized: `preparePackage` un-defused (`./src_` → `./src`, `./dist_` → `./dist`; the prepare scripts and offline-safe disposable-domains before-hook were already wired, just disabled), `main` flipped to `dist/manager/index.js`, the bin shim requires `dist/cli/index.js`, `start` runs `prepare:watch` like every other framework, and `prepublishOnly` prunes the self-test fixture's node_modules from both src and dist. dist mirrors src at identical depth so `__dirname`-relative paths resolve unchanged; `src/` still ships (the test corpus deep-requires it). Verified: standalone suite via bin→dist, full sandbox corpus 1203 passing via consumer `npx mgr`→dist, cross-stack e2e 11/11, pack-smoke (tarball ships 432 dist files, fixture symlinks excluded by npm pack, scratch-installed `mgr version` runs from dist). - `packages/client` (web-manager) adopted `@omegajs/account`: `modules/auth.js` deleted its hand-rolled `DEFAULT_ACCOUNT` + deep-merge `resolveAccount` + `resolveSubscription` body and now imports the shared engine — account docs resolve byte-identically to the backend (canonical semantics: junk-type coercion, unknown-key stripping outside `$passthrough` branches, full defaults incl. `flags`/`activity`), and `resolveSubscription` gains `everPaid` (additive; the wrapper keeps only web-manager's storage-fallback glue). Published tarballs stay self-contained via the vendor after-hook (`dist/vendor/account/`). Gates: client suite 74 passing, cross-stack e2e 11/11 (the e2e's "BEM wrote the user doc" marker moved from `metadata.created.timestamp` — which the canonical engine fills even for fallback accounts — to `api.clientId`, which only the backend generates), pack→scratch-install smoke clean.

### Fixed
- Devkit vendor tool died with `ENAMETOOLONG` on backend-manager's dist: `jetpack.find` follows symlinks during traversal (matching exclusions don't prune the walk), so the host-dist scan recursed forever through the self-test fixture's circular `backend-manager → package root` symlink. The scan now uses a symlink-safe walker that also skips `node_modules` and the vendor output — fixture/dependency code inside dist is not host code and is neither scanned nor rewritten. Regression-tested with a circular-symlink + node_modules fixture (devkit suite 32 passing).
- Sandbox `test:backend` never actually worked from the brand root: `npm run test:offline --workspace=apps/backend` resolved workspaces against the MONOREPO root (sandbox-brand is itself a root workspace and workspace globs don't recurse), so the flag found nothing — the corpus had only ever been run from inside `apps/backend`. Now `cd apps/backend && npm run test:offline`; CI's sandbox job would have failed on first push.
- `packages/client` (web-manager) had **no auth-emulator support** — Firestore had a `FIREBASE_EMULATOR_CONNECT` path but auth never called `connectAuthEmulator`, so signin/signup against an emulated backend silently hit LIVE Firebase Auth. Found by the cross-stack e2e (dogfood catch).
- `packages/client` emulator-mode **account reads hit LIVE Firestore**: the emulator connect lived only in the lazy firestore module, but the auth module reads accounts via `manager.firebaseFirestore` directly — unless page code happened to touch `manager.firestore()` first, account fetches went to production. Both connects now live in `_initializeFirebase()` at instance-creation time (auth :9099, firestore :8080, one gate); the duplicate block in the firestore module was removed. Suite unchanged at 73 passing.
- `packages/backend` rules tests ignored the firestore emulator port from firebase.json — the runner never passed it to the rules client, so every rules test timed out for any consumer on a non-default port (found by the sandbox's first dogfood run). The runner now passes `emulatorPorts.firestore` through.
- `packages/backend` content/post 404 tests hit LIVE GitHub search even in normal (non-extended) test mode — the route 500s without `GH_TOKEN`, failing every token-less consumer. Both suites exercising the route (`test/routes/content/post.js` and the `--legacy`-only `test/functions/general/fetch-post.js`) now skip without a token, using the same static-skip pattern as the mailbox-key tests. Logged (not fixed): BEM doesn't support custom emulator ports at all — `Manager.getApiUrl()`/`getFunctionsUrl()` hardcode `localhost:5002`/`5001` in dev/testing; harmonization candidate.
- Root `.gitignore` comment claimed `packages/*/dist` is tracked — it never was (each package's own `.gitignore` ignores its dist, matching framework-repo convention; prepare-package regenerates dist on install/pack/publish).
- `packages/desktop` package.json `files`: added `scripts/` — the published electron-manager@1.12.0 declares `postinstall: node scripts/sync-nvmrc.js` but never shipped the script, so every FRESH consumer install fails on npm today. Found by the pack→scratch-install smoke; verified fixed (tarball ships the script; postinstall syncs consumer .nvmrc).
- `packages/desktop` test runners (`src/test/runners/electron.js`, `boot.js`): electron now resolved via `require.resolve('electron', { paths: [projectRoot] })` instead of hardcoded `<root>/node_modules/electron`, so hoisted npm-workspace installs are found. Behavior unchanged for standalone consumers. Result: desktop suite 751 passing (was 299 with 47 hoisting skips).
