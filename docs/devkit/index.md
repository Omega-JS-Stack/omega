# @omega.js/devkit

Shared build-time internals for the OMEGA frameworks. **Private workspace package — never published to npm.** (The vendorable-private set is devkit, config, account, template-kit, analytics, monitoring — `VENDORABLE_PACKAGES` in [tools/vendor.js](../../packages/devkit/tools/vendor.js) is the SSOT.)

## How frameworks consume it

Frameworks require modules by name (`require('@omega.js/devkit/logger')`) and declare `@omega.js/devkit` as a **devDependency** (workspace-linked in the monorepo, absent from consumer installs). At prepare time, each framework's `preparePackage.hooks.after` runs [tools/vendor.js](../../packages/devkit/tools/vendor.js) (with `afterBlocking: true`, so a vendor failure aborts the prepare instead of warning past it; it runs SECOND, behind `prepare-guard.rewire()`, and an aborted prepare still ends with the #350 gate wired, [#870](https://github.com/Omega-JS-Stack/omega/issues/870)), which copies the referenced modules into the framework's `dist/vendor/devkit/` and rewrites the requires to relative paths, so published tarballs are self-contained with zero **private** `@omega.js` references (enforced by CI's pack-smoke). Published `@omega.js` RUNTIME deps (desktop/extension's `@omega.js/client`) are never vendored: they stay normal package requires and resolve from the consumer install.

The closure covers the VENDORED trees too ([#739](https://github.com/Omega-JS-Stack/omega/issues/739)): a vendored module's own cross-package requires are rewritten to the sibling vendored copy (`dist/vendor/devkit/license.js` requires `../config/index.js` and `../account/index.js`), and any vendorable that only a vendored file needs is vendored beside it even when the host references it nowhere. Before that the copies shipped those specifiers verbatim, which resolved through the workspace symlinks in the monorepo and threw MODULE_NOT_FOUND on a published install, the private packages never being there. A published runtime dep stays a package require inside the vendored trees as well.

Vendored code resolves its deps (chalk, node-powertools) from the HOST framework's dependencies — the vendor tool fails if the host doesn't declare them.

| `src/bundle.js` | The ONE esbuild wrapper every framework bundles through ([#736](https://github.com/Omega-JS-Stack/omega/issues/736), part of [#128](https://github.com/Omega-JS-Stack/omega/issues/128)): `bundle({ frameworkRoot, entries, outdir | outfile, target, format, splitting, mode, dev, define, plugins, ...esbuild })` → esbuild's result with the metafile on in `'build'` mode, and `{ context, dispose }` in `'watch'` mode (the startup build is the watcher's own and lands AFTER the call resolves, so there is no result to hand back; a caller needing it reads its own plugin's `onEnd`, which is the only hook that sees rebuilds too). ## Boot preludes ([#890](https://github.com/Omega-JS-Stack/omega/issues/890))

Every framework CLI boot runs two steps before the verb, in this order: the freshness guard (`freshnessBoot`, [local-dev.md](../shared/local-dev.md)), then the boot PRELUDES. All five entries (web, backend, desktop, extension, manager) carry the identical call, which is the parity the list depends on:

```js
require('@omega.js/devkit/preludes').runPreludes({ verb: process.argv[2], targetDir: process.cwd() });
```

The freshness guard was the ONLY seam above every verb, so anything else the whole CLI surface has to settle first had nowhere to live and lived nowhere: a brand clone left pointing at a redirected GitHub repo was checked by no verb at all.

**A prelude is one file exporting `{ name, verbs, run }`**, with one concern. `verbs` is `'all'`, one verb name, or a list of them, and the runner runs the MATCHES in list order. The filter reads the verb as TYPED (the first positional, before any framework's alias table resolves it, since the tables are the frameworks' and this runs above them), so a flag where the verb goes (`-v`) and a bare `omega` are both "no verb": only an `'all'` prelude covers them. A prelude declaring no usable `verbs` fails loudly at the filter, naming itself, before anything has run.

**A prelude is CHEAP and NON-INTERACTIVE**: local reads, at most one network call, never a prompt. Anything heavier is a manage op in its own service, where a walk reports it and a dry run plans it. Nothing is cached per process: a dispatcher hop that re-enters a `run()` runs the preludes again, and every prelude being idempotent, the second pass is a local read that finds its work already done.

**A prelude that STOPS the run throws with one line of why**, which the runner prints (prefixed `omega:`, no stack) before exiting 1: the same presentation the freshness guard's loud stops use, so a refused boot reads the same whichever step refused it. Everything a prelude expects to find in the world (no brand, no `.git`, no network) is a silent no-op instead, because a boot step that narrates the ordinary would print on every verb forever.

| Prelude | Verbs | What it does |
|---|---|---|
| `origin-heal` | `all` | Asks GitHub about the repo the checkout's `origin` already names (`gh api repos/<owner>/<name>`, which follows GitHub's own 301 after a transfer or a rename) and points the remote at the `full_name` that answer carries, printing `origin healed from <old> to <new>`. The REDIRECT is the authority, not the config: a brand is healed onto wherever its repo actually moved, config or no config, at the price of one GitHub read per boot (bounded at ten seconds, so a stuck network lands on the same silent unreachable case as an offline one). A transfer leaves every clone on the old address and git follows the redirect silently, so nothing ever complained until a push landed somewhere the brand no longer is (the `omega-omega` transfer into `Omega-JS-Stack`, 2026-09-12). Then DRIFT, on whatever that answer was: the WHOLE slug against the source repo the config derives (`@omega.js/config`'s `repoDrift`, case-insensitive, so a rename drifts as surely as a transfer, [#934](https://github.com/Omega-JS-Stack/omega/issues/934)) prints `origin is <slug> but config derives <derived>: fix repo.org in config/omega.json5 or move the repo` and nothing more, because a fatal boot would lock out the verbs that fix it and this prelude never writes config. The verbs that ACT on the derived repo (the manage walk's repo service, the deploy lane) refuse on the same line instead. Every other case is a silent no-op: no brand root, no `.git` AT the brand root (never a walk up, so a brand nested in another repo cannot have the enclosing remote rewritten), no `origin`, a non-GitHub remote, a slug GitHub answers as itself (converged), a repo GitHub 404s (it is gone), or a GitHub it cannot reach. The WRITE is the one loud failure: a `set-url` refused after a `get-url` just answered is a broken invariant, not an external condition |

## Rules

- `src/` holds ONLY vendorable runtime modules — anything in `src/` ships inside every framework's dist. Build-side tooling goes in `tools/`.
- Tests: `npm test` (node:test). Migrates to the shared devkit test runner once that slice is extracted.
