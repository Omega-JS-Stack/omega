# Common Mistakes to Avoid

1. **Defining a local `escapeHTML` / `sanitizeURL` helper**: use the canonical inline form `omega.utilities.escapeHTML(value)` / `omega.utilities.sanitizeURL(url)` at every call site. Do NOT alias / destructure / `.bind()`. This is the most common XSS-introduction vector in @omega.js/extension extensions.
2. **Using raw `chrome.*` instead of `extension.*`** — Use the extension API wrapper for cross-browser compat (Chrome / Firefox / Edge).
3. **Putting service-worker-incompatible code in `background`** — Service workers can't hold WebSockets or long-running state. Use the `offscreen` component for persistent work.
4. **Trying to share `omega` state across components**: each component context has its own `omega` instance in its own JavaScript context. Use `omega.messenger` / `extension.storage` to communicate.
5. **Writing `<html>`/`<head>`/`<body>` in component views** — Views are HTML fragments; @omega.js/extension wraps them with `page-template.html` at build time.
6. **Hand-editing `dist/manifest.json` or `dist/*` files** — Edit `config/manifest.json` (or component sources); @omega.js/extension regenerates dist on every build.
7. **Expecting a consumer `npm install` to change what a bundle ships**: the bundler's framework-deps hook resolves every name @omega.js/extension DECLARES from the framework's own `node_modules/`, so declaring `firebase` in the consumer never swaps the bundled copy. Code that runs under plain node (`hooks/`) is the other half: declare the package yourself, or load the framework's copy with `require('@omega.js/extension').require(name)`; the build warns and names both ([the one rule](../shared/local-dev.md#using-what-the-framework-depends-on)).
8. **Touching Firebase directly in consumer code**: Firebase is owned by @omega.js/client. Consumer code NEVER does `import firebase from 'firebase/app'` or `require('firebase')`. Instead: the context's instance, `omega.auth`, `omega.firestore`. Same rule on every OMEGA browser surface.
