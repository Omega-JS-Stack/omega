# Wave 4 Review Findings — config + client + account + template-kit (2026-07-23)

## Context

This is an internal code-quality review of **Ian's own pre-release codebase**, commissioned by Ian and carried out on the repo he owns. It is a staged, wave-by-wave hardening pass over the OMEGA monorepo: each wave reads a package group, records defects, and ships one remediation checkpoint. No third-party system is involved, no production data is accessed, and every item below is a defect in first-party code that the same effort then fixes.

The packages are unpublished (`private: true`, local `file:` specs, zero npm releases). Wave 3 (web engine + themes) shipped as cp264/cp265. This document is wave 4: `packages/client` (the shared frontend runtime consumed by web/desktop/extension), `packages/account`, `packages/config` (the omega.json5 loader/merge/validator), and `packages/template-kit` (the Liquid engine + tags). Reviewer A read client + account; reviewer B read config + template-kit. The account package returned no findings.

Findings are ordered by priority (one P1, fix first). Each entry names the defect, the file, and the fix. All 17 findings were re-read in source by the coordinator before filing.

## Client + account (reviewer A)

- **F1 (P1)** — Sentry's `beforeSend` opens with `const startTime = this.manager.config.page.startTime || Date.now()`, but no surface ever writes a `page` config key (client defaults, the web `window.Configuration` blob, desktop/extension bridges — none). The property access throws inside `beforeSend` on every captured event, and the Sentry SDK drops an event whose `beforeSend` throws — so on any brand with a real DSN, error reporting reports nothing. `packages/client/src/modules/sentry.js:91`. **Fix:** read a value that exists (module-load timestamp or `config.buildTime` fallback) and never deref a config branch nothing writes.
- **F2 (P2)** — The bindings condition parser's operator alternation is `(===|!==|==|!=|>|<|>=|<=)`: `>` is tried before `>=`, so the `>=`/`<=` branches are unreachable — `usage.credits.monthly >= 5` parses as `>` against the string `"= 5"` and evaluates false. docs/bindings.md advertises both operators. `packages/client/src/modules/bindings.js:265`. **Fix:** reorder longest-first `(===|!==|==|!=|>=|<=|>|<)`.
- **F3 (P2)** — `auth.listen()` short-circuits (immediate signed-out callback) only when `_resolveFirebaseConfig()` is falsy, but `initialize()` boots Firebase only when the blob has an `apiKey` — a projectId-only config (a designed-for state, per the init comment) passes the guard while `onAuthStateChanged` never registers and `_authReady` never resolves (`index.js:543` is its only resolver). `{ once: true }` listeners hang forever; persistent listeners never fire. `packages/client/src/modules/auth.js:76`. **Fix:** guard on the same condition init uses: `!this.manager._resolveFirebaseConfig()?.apiKey`.
- **F4 (P2)** — Sentry user enrichment reads `storage.get('user.auth.email')`/`('user.auth.uid')`, but auth writes its state under the `auth` storage key (`auth.js:110` — shape `{ user: { email, uid } }`); nothing writes a `user` key. Every event ships empty identity — the read is a legacy web-manager path. `packages/client/src/modules/sentry.js:105-106`. **Fix:** read `auth.user.email` / `auth.user.uid`.
- **F5 (P2)** — Both `onSnapshot` implementations (doc at ~110, query builder at ~210) return an unsubscribe closure over a placeholder noop that is only replaced after the lazy `_ensureInitialized()` resolves. Unsubscribing before that (immediate teardown, or first-ever Firestore call with the dynamic import in flight) calls the noop, then the real listener attaches and can never be detached. `packages/client/src/modules/firestore.js:110,210-233`. **Fix:** cancellation flag — the `.then` checks it before subscribing; the returned function sets it and calls the real unsubscribe if present. Both sites.
- **F6 (P3)** — `Device.initialize()`'s new-session branch reads defensively (`this.data.session?.count || 0`) but writes `this.data.session.count`/`started` directly; stored data (raw `JSON.parse` of localStorage/extension storage) missing `session` throws, and `manager.initialize()` rethrows — one malformed stored entry breaks the whole client boot on every page load. `packages/client/src/modules/device.js:65-68`. **Fix:** `this.data.session = this.data.session || {}` before the writes.
- **F7 (P3)** — analytics-core exists so identity/payload math cannot drift between surfaces, and exports `normalizeEventName` (GA4 charset/length rule). Desktop applies it (`packages/desktop/src/lib/analytics.js:228`); the browser engine passes `eventName` raw — no caller of `normalizeEventName` exists in packages/client, so `event('signup-completed')` lands on desktop and is rejected by GA4 from web/extension. `packages/client/src/modules/analytics.js:139`. **Fix:** normalize in `event()`/`_sendViaFetch`.
- **F8 (P3)** — `mergeUsageIntoBindings` rebuilds each usage key with `limit: limits[key] || 0`; a key present in `usage.current` but absent from `usage.limits` clobbers the catalog-seeded limit with 0 after the first API response. `packages/client/src/modules/request.js:132`. **Fix:** `limit: limits[key] ?? existing[key]?.limit ?? 0`.
- **F9 (P3)** — `listen()`'s account-fetch try/catch and its Sentry capture are dead: `_getAccountData` has an inner catch that logs to console and returns null, so the outer capture written for exactly this failure never fires — a Firestore permission/network error silently degrades to a basic-plan resolved account. `packages/client/src/modules/auth.js:92,282-285`. **Fix:** move the Sentry capture into `_getAccountData`'s catch (keep the null-degrade so the page still settles).
- **F10 (P3)** — Every FormManager joins the module-level `_instances` Set for the shared beforeunload handler and nothing ever removes it — no destroy path. A dirty form torn out of the DOM keeps blocking navigation forever, and each re-render leaks an instance. `packages/client/src/modules/form-manager.js:77`. **Fix:** `destroy()` (removes from the Set, detaches per-instance listeners) + the shared handler skips instances whose `$form.isConnected` is false.
- **F11 (P3)** — `notifications.initialize()` resolves the web-push VAPID key from `config.firebase.messaging.config.vapidKey`, which no config producer writes (client defaults, config package, web Configuration blob, bridges) — the key is always null and brands cannot supply one through omega.json5 even though the code path expects it. `packages/client/src/modules/notifications.js:8`. **Fix:** wire the slot through the config chain (it needs to work — the W7 standard), or delete the read if notifications are deferred.

## Config + template-kit (reviewer B)

- **F12 (P2)** — `SECRET_KEY_PATTERN` is `/(secret|privateKey|apiSecret)$/i`: snake_case `private_key`/`private_key_id` (the pasted-service-account classic this guard exists for), `secretKey`, `password`, `token`, `accessToken` all pass the hard-fail; the `apiSecret` alternative is dead (already matched by `secret$`). AGENTS.md promises "the validator hard-fails secret-shaped keys" — the pattern under-delivers. `packages/config/src/secrets.js:12`. **Fix:** extend to the promised shapes (password/token/credential suffixes, snake+camel private key, api/client/access/refresh secrets+tokens) while keeping publishableKey/clientId/apiKey passing; regression cases per shape.
- **F13 (P2)** — The Liquid adapter's `buildLookup` resolves every unquoted tag argument as a scope path (`context.getSync(split('.'))`); bare literals like `640`, `true`, `false` resolve to undefined, so `{% uj_image "/a.png", max_width=640, webp=false %}` silently drops both options (verified by live render). The Ruby reference evaluated bare literals, so ported templates break the "port verbatim" contract. `packages/template-kit/src/register-liquid.js:38`. **Fix:** evaluate bare literals (true/false/nil/numeric) before the scope lookup, mirroring jekyll-compat's `resolvePath`.
- **F14 (P3)** — Two parsers for the same `key=value` tag syntax drifted: `parseOptions` (uj_image/uj_video) keeps null when an unquoted value's lookup misses; `parseImageOptions` (uj_member/uj_post image-tag) falls back to the literal text. Same purpose, divergent semantics — the mirrored-implementation rule broken inside one package. `packages/template-kit/src/variable-resolver.js:99` vs `tags/collections.js:29-33`. **Fix:** one implementation with literal fallback; collections.js imports it.
- **F15 (P3)** — `runSchema` wraps a functional `rule.required(config)` in `catch (_) { isRequired = false; }` — a throwing first-party schema rule silently makes the field optional and validation reports success. Loud-failures violation. `packages/config/src/validate.js:62`. **Fix:** push a named error (`config.<path> required() threw: <message>`) instead of swallowing.
- **F16 (P3)** — `loadConfig` has a functions/ → app-root fallback (`load.js:221-224`) but `hasOmegaConfig` does not (`load.js:78-80`), so for a standalone backend with the authored file at the app root the probe says false while the load would succeed; backend commands gate on the probe with the functions dir and proceed with empty config — the cp142-class failure the probe's own docstring says it prevents. **Fix:** mirror the fallback in the probe so probe and load always agree.
- **F17 (P3)** — media.js interpolates caller-supplied strings into HTML attributes unescaped (`data-icon="${iconName}"` at 65; alt/class/style/width/poster in buildImageHtml/buildExternalImage/videoAttributes), while `tagMissing` in the same file already escapes its slug (line 142) — a legitimate quote in frontmatter-derived alt text produces malformed HTML at build time. `packages/template-kit/src/tags/media.js:65,260-268,320-329,385-402`. **Fix:** small `escapeAttr` helper applied to every attribute interpolation.

## Status (2026-07-23, cp266 — SHIPPED)

**All 17 findings resolved and tested** in one remediation batch. F13's fix landed one layer deeper than the finding named — in `resolveVariable` (variable-resolver.js) rather than the LiquidJS adapter's `buildLookup` — so every engine adapter and every `uj_*` tag argument gets the Ruby-parity literal evaluation, not just the key=value options (that is the Ruby behavior: Jekyll's `context[...]` evaluated literals everywhere). F14's unified parser settled on Ruby's preferLiteral rule after the commit-time bugs lens showed the two Ruby lanes themselves disagreed (image lane: null on miss; post lane: literal fallback) — bare words stay literal, dotted misses yield null, so both lanes' sane behaviors survive. The same review hardened the F6 device guard against stored primitives. F17's escaping covers the `src`/`srcset` interpolations too (escaped once at derivation in each builder); it is a deliberate departure from the Ruby original, which interpolated these attributes unescaped — the cp161 missing-icon-slug escaping set the precedent. F11 took the wiring fix (notifications is live on the web surface — auto-subscribe + dashboard section): new `cloud.messaging.vapidKey` schema slot, web engine bridge, cloud-first client read. Regression coverage: 10 findings carry behavioral pins each seen red against the pre-fix source (device gets a second one for the primitive case); the five SDK-coupled fixes (F1/F3/F4/F5/F9) plus the FormManager teardown carry source pins (also seen red pre-fix), the client set in `packages/client/test/tests/wave4-pins.test.js`. Client 162, config 136, template-kit 46, full root battery EXIT 0. Details: CHANGELOG cp266.
